# Proposal

## Why

The `/llm-wiki` page contradicts itself about the course. Above the form it says "dam znać, gdy ruszy kurs"; the success screen says "Kurs już ruszył"; its last line says the guide and accelerators "będą w kursie"; and the meta description repeats "dam znać, gdy ruszy kurs". Meanwhile the course is public and the page links to it from below the form (`/llm-wiki/kurs`). A visitor reads three different launch states on one page (PL-464).

The signup also changed under the copy. Since `migrate-waitlist-to-resend` the endpoint stores the address and sends **no email** (single opt-in, no confirmation mail — listed under Non-Goals in that change's `design.md`). The success screen is therefore the visitor's only confirmation, and its header ("Jesteś na liście!") does not say what was saved.

## What Changes

- The success header becomes "Adres zapisany!" and the text under it says plainly that the address is saved and that news arrives by email. It no longer announces a course start.
- The paragraph above the form describes the list by what it delivers (the free template at once, news about further materials by email) instead of by a launch event.
- The meta description drops "gdy ruszy kurs" for the same reason.
- The closing line of the success screen ("Pełny przewodnik + akceleratory … będą w kursie. Odezwę się.") is removed. Lesson 5 already says the accelerators are separate paid packs, so the line was wrong as well as stale.
- The `llm-wiki-landing` spec is corrected where it no longer matches the page: the success header text, and the scenario that says there is no link to `/llm-wiki/kurs` before signup (the link has been there, ungated, since the course was wired into the site).
- A new requirement records the rule so a launch announcement does not return to the page.
- The `@sitemapUpdated` marker in the page and `public/sitemap.xml` move to the change date.

No email is added. A welcome or confirmation mail is a separate decision for the owner; `emails/` holds a launch broadcast and a release announcement, not a confirmation template.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `llm-wiki-landing`: the success-screen requirement (header text, course link, ungated course link before signup) is restated; one requirement is added for the signup copy.

## Impact

- **Copy (PL only; the page has no English version and no `/en` mirror):** `src/pages/LlmWikiLanding.jsx` — four strings plus the `@sitemapUpdated` marker.
- **Generated, tracked:** `public/sitemap.xml` (`<lastmod>` of `/llm-wiki` only), regenerated by `npm run blog:sitemap`.
- **Tests:** `tests/e2e/llm-wiki-landing.spec.js` and `tests/e2e/llm-wiki-course.spec.js` assert the old header; both move to the new one, and the landing spec gains one test for the copy rule.
- **Docs:** one Work Guidance bullet in `src/AGENTS.md` records the trap. `api/AGENTS.md` loses a line that says `npm run test:unit` is broken on Node 24 (it runs, 14/14, and `tests/AGENTS.md` says the same).
- **Not touched:** the endpoint, `CourseHub` and `CourseLesson` CTAs ("dam znać, gdy ruszą gotowe paczki wiedzy" — about paid packs, still accurate), the `llm-wiki-course` spec.
