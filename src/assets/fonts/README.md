# Self-hosted fonts

Generated by `npm run fonts:fetch` (`scripts/fetch-fonts.mjs`). Do not edit the
`.woff2` files or `src/styles/fonts.css` by hand — regenerate instead.

| File | Family | Subset |
| --- | --- | --- |
| `inter-latin.woff2` | Inter (variable, 300–700) | latin |
| `inter-latin-ext.woff2` | Inter (variable, 300–700) | latin-ext |
| `fira-code-latin.woff2` | Fira Code (variable, 400–600) | latin |
| `fira-code-latin-ext.woff2` | Fira Code (variable, 400–600) | latin-ext |

`latin-ext` is required, not optional: it carries ą ć ę ł ń ó ś ź ż. Dropping it
would silently fall back to a system font for most Polish text on the site.

## Why these live under `src/`, not `public/`

`src/styles/fonts.css` references them with a **relative** path, so Vite
fingerprints each file and emits it to `/assets/`. That path already carries
`Cache-Control: public, max-age=31536000, immutable` from `vercel.json`.

Served from `public/fonts/` they kept their literal names, fell through to the
catch-all header rule, and went out as `max-age=0, must-revalidate` — a
revalidation round trip per font on every page load. The hashed filename is also
what makes a year-long cache safe: regenerating a font changes its name, so a
returning visitor is never served a stale file.

An absolute `/fonts/…` URL in the CSS would defeat this — Vite treats those as
public-dir paths and leaves them untouched.

The `<link rel="preload">` for `inter-latin` is injected by the
`preload-body-font` plugin in `vite.config.js`, because the fingerprinted
filename is not knowable until the bundle exists.
