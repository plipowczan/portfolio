## 2. llms.txt / llms-full.txt
- Present, HTTP 200: /llms.txt is 23,028 bytes, /llms-full.txt is 1,173,161 bytes.
- Spec conformance (llmstxt.org): H1 title + blockquote summary + H2 sections with list items of form [title](url): description. Matches spec shape. No malformed markdown found.
- Content check: 33 PL posts (src/content/blog) + 30 EN posts (src/content/blog/en) + 10 course lessons (src/content/kurs) + 9 project case studies -- all present and current against the live file. Generated by scripts/generate-llms-txt.js, invoked from the same build-with-prerender.mjs chain as the sitemap generator (scripts/update-sitemap.js). Both read the content folders directly at build time through the same DOC_FILES filter, so the two artifacts cannot silently diverge from each other or from what is published. Low staleness risk.
- Gaps: no "Optional" section per spec convention (not critical at this post count); llms.txt never links llms-full.txt, so a crawler reading only the index has no signal the full-text variant exists, even though it already contains every post's complete body; no per-page markdown route for a single cited URL; no "last generated" timestamp in the file.

FAQ schema with question-phrased entities exists on both sampled posts, but visible H2 headings are mostly feature/section labels, not questions -- the question framing currently lives only in invisible JSON-LD.
## 5. Authority and entity signals
Person schema is present on every page checked (home and posts): name, jobTitle, url, sameAs (GitHub, LinkedIn only), knowsAbout, worksFor (Qamera AI). The same JSON-LD block is reused verbatim across pages, which is correct for entity consistency. BlogPosting schema (author, datePublished, dateModified, publisher) confirmed on every post checked.

Two confirmed gaps combine into the biggest authority problem on the site: (1) the Person schema has no @id, so nothing formally links the schema instances together as the same node across pages or ties them to a canonical URL for the entity itself; (2) there is no author or about page anywhere on the site (no /o-mnie, no /about, confirmed absent from src/pages). The practical effect: "Pawel Lipowczan" exists in structured data and in repeated bylines, but there is no single human-readable page an LLM (or a human fact-checker) can land on to see the bio, credentials, and full sameAs list in one place. This is worse than a missing bio on an existing page -- it means the entity has no canonical home at all, which weakens exactly the kind of entity resolution that lets a model attribute claims to a real, resolvable person rather than an anonymous byline string. sameAs is also thin either way (GitHub + LinkedIn only, no YouTube/Reddit/X), which matters given the brand-correlation data showing YouTube (about 0.737) and Reddit as the strongest external corroboration signals.

dateModified equals datePublished on every post sampled -- updates are not tracked independently, which will matter once fast-moving posts (n8n pricing, Claude Code features) get revised.
